# DeepCode 插件的配置与生命周期契约

本规范约束后续插件改造。当前实现不因此自动视为通过；逐项缺口由开发任务跟踪，单次调查与运行结果留在 `.local/`。

## 对齐 DSH，区分功能开关与插件卸载

DSH 使用 Cordis 组合插件。注册的服务、工具和槽位随所属上下文释放；自有定时器、DOM 监听、子进程和原生租约必须有对应 disposer。硬依赖消失会导致消费方卸载，这是正常的依赖传播，不代表所有插件都能任意移除而功能完全不变。

DeepCode 增加以下产品要求：可选功能可以独立停用和恢复；用户数据、其他 Agent 和不依赖该功能的界面继续工作。底层 fs、shell、WebView 布局等必需服务不提供会造成不可用状态的普通开关，应在插件清单标明“平台必需”，替换通过受控装配和重启进行。

| 操作 | 契约 |
|---|---|
| 关闭可选功能 | 立即阻止新工作；停止空闲采样/轮询/进程/租约，或进入明确的排空状态；保存配置和草稿 |
| 活跃任务期间关闭 | 默认拒绝并说明现有任务，或实现明确的排空；禁止静默杀掉用户任务、丢转录、隐式切换 Harness |
| 开启功能 | 恢复一个实例，不重复注册事件、界面、进程；需要系统授权时在能力入口处理 |
| 卸载插件 | 撤销自身资源与贡献；缺少可选能力时消费方降级，不能保留失效引用 |
| 重装/热替换 | 幂等恢复；旧实例的异步响应、退出事件不得污染新实例 |
| 重启应用 | 配置生效，持久数据保留；停用的功能不因探测或查看设置被启动 |

## 统一设置入口

用户可选插件的配置统一放在 DSH 的“设置 → 插件 → 可配置插件”。使用 Host settings namespace 与 `settings.plugin.item` 的相同 key 配对；通过标准 settingsScope 与 revision 并发写入协议更新。不要只换客户端槽位而漏掉 Host 命名空间，否则卡片可能不出现。

旧 localStorage 开关需要一次性迁移：已有 Host 用户值优先，缺失时才导入旧值；导入成功且校验回读后标记完成。语音待插入文字、工作台泳道与草稿不是开关配置，不可随迁移删除。原生系统授权（麦克风、存储、ADB、合盖策略）继续由 Android 管理，插件卡片只提供入口和状态。

账号密钥不写入通用 settings。Codex 登录和退出继续使用已认证的账号 API；功能 enabled 与实际进程状态必须一致，显示的 connected 不能硬编码为 true。

插件配置页保留独立启停控制；整个插件卸载后其卡片消失属于正常行为，重新安装应通过插件清单/受控装配入口，不能依赖已经卸载的卡片。

## 依赖与原生能力

- Voice Deck 的基础聊天、附件和文字输入只依赖会话与编辑器；语音、手柄必须是可选集成。使用受生命周期管理的可选注入或目标 Cordis 版本支持的服务查询；禁止读取未声明的 ctx 属性后仅加可选链来规避错误。
- Android 壳提供平台桥和能力租约；产品开关由插件拥有。关闭特效应释放双屏状态/模糊资源，不改变用户系统合盖设置。
- Debian 工具卸载不能删除 rootfs 或工作目录。后台任务必须有稳定的所属记录、取消与结果查询路径；工具入口生命周期与任务进程生命周期分别定义。
- 构建期补丁、版本守卫和必需平台适配不是运行时可选功能；不能把 UI 开关描述成可以卸载这些补丁。
- Codex Skills 是另一种扩展机制，不是 Cordis 插件；媒体、字幕、安卓开发、会话监控技能不计为 DSH 可配置插件。

## 验证要求

每个可选插件至少覆盖：初始停用、开启→关闭→开启、重复操作、实际卸载→重装、依赖缺失/恢复、执行中关闭、页面卸载与重连。检验实际副作用而不仅是 checkbox：注册数量、定时器、请求、进程、租约以及草稿/会话身份。

契约测试先在隔离环境运行；Android 桥相关行为再在平板验收，折叠专有资源只在用户安排的 Fold 验证。开发文档记录可复用方法；PID、会话内容、设备截图、测试结果不入仓库。
