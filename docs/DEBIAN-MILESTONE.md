# Debian 执行环境里程碑

目标建立于 2026-09-09：保留 Android 原生 TS Harness，新增可安装、可重建的 Debian/proot 执行环境插件，使 Agent 能使用 Linux 软件生态。

## 验收顺序

1. 固定双 ABI 的 Debian rootfs 和 Android proot 来源、版本、SHA-256，提供可复现获取脚本。
2. 在现有 APK 用户域验证 proot、glibc 程序、DNS 和包管理；处理 Android 特有问题后再封装。
3. 实现 TS 插件：环境状态、安装、命令任务、任务查询和取消；宿主凭据不注入 guest，用户项目显式映射。
4. 验证安装/失败恢复及重建；任务保存状态，宿主重启后不静默重放。
5. 模拟器验收软件包安装、FFmpeg、带原生编译的开发任务和 Web 服务。
6. 模拟器验收内部/共享/虚拟外置工作区、撤权/缺失目录、后台与取消，探测隔离边界并标明 partial。
7. 打包两个 ABI，完成现有门禁和关键回归，交付 LAN 下载与 ARM64/HyperOS 实机清单。
8. 更新工程文档、来源与验证记录，提交到现有 Gitea 仓库。

## 范围与原则

- Debian/proot 是 Linux 兼容后端，不宣称内核级安全容器，不把 rootfs 当作完整 Agent 沙箱。
- rootfs/工具/缓存放应用私有持久目录；用户项目和输出仍在用户选择的存储，不静默改为沙盒副本。
- 原生 Shell 保留；新能力通过插件提供，不修改上游 Harness 核心。
- 不将 HyperFrames 完整视频渲染纳入本里程碑；先交付媒体工具与开发执行环境。
- 无实机时只能验收模拟器并交付 ARM64 包，不宣称小米设备性能与长期后台通过。
- 所有故障注入只作用于专用模拟器和本里程碑新建测试目录。
